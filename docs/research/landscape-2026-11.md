# Landscape check, 2026-11-27

Every claim the v2 design makes about another tool, product, paper or library, checked
against the project's own repository, documentation or paper on **2026-11-27**. Repos
were read with `gh api` and shallow clones (no third-party code was run, except the two
Cedar Python packages, which were installed from wheels in a scratch virtualenv for a
smoke test). Verdicts: **confirmed**, **partial** (true with a caveat that matters),
**wrong**.

## Research and standards

| Item | Verdict and evidence |
|---|---|
| FIDES, arXiv 2505.23643 (v2 2025-09-03) | confirmed: Microsoft; a planner with confidentiality/integrity labels and dynamic taint tracking that "deterministically enforces security policies"; code at `microsoft/fides` (MIT). |
| CaMeL, arXiv 2503.18813 (v2 2025-06-24) | **partial:** authors are from Google, Google DeepMind and ETH Zurich (not DeepMind alone), and the paper claims "provable security" (77% of AgentDojo tasks solved vs. 84% undefended) while admitting side channels. It does replace the agent loop: a privileged LLM writes code, an interpreter checks capabilities on values, a quarantined LLM parses untrusted data. |
| Design Patterns, arXiv 2506.08837 (v3 2025-06-27) | confirmed; authors from Invariant Labs, IBM, EPFL, ETH Zurich, Google, Microsoft and others. Patterns: Action-Selector, Plan-Then-Execute, LLM Map-Reduce, Dual LLM, Code-Then-Execute, Context-Minimization. |
| Meta, "Agents Rule of Two" (2025-10-31) | confirmed. Within a session an agent should have at most two of: [A] "can process untrustworthy inputs", [B] "can have access to sensitive systems or private data", [C] "can change state or communicate externally". If all three are needed without a fresh session, it "requires supervision — via human-in-the-loop approval or another reliable means of validation". |
| Willison, "The lethal trifecta" (2025-06-16) | confirmed: "access to your private data", "exposure to untrusted content", "the ability to externally communicate in a way that could be used to steal your data". |
| LlamaFirewall, arXiv 2505.03574 | confirmed: PromptGuard 2, AlignmentCheck (experimental), CodeShield, custom scanners. |
| MCPTox, arXiv 2508.14925 (v2 2026-09-29) | confirmed; repo `zhiqiangwang4/MCPTox-Benchmark` HEAD `630121b327` (2026-11-15). License added 2026-11-14: code MIT, data CC BY 4.0 for the rights MCPTox holds (copied tool descriptions keep their upstream licenses). 485 *poisoned* tools; the **353 authentic tools** from 45 servers exist only as plain text inside system prompts (`response_all.json`), without JSON schemas. |
| OWASP Top 10 for Agentic Applications 2026 | confirmed (ASI01 Agent Goal Hijack … ASI10 Rogue Agents; CC BY-SA 4.0). |
| OWASP MCP Top 10 | confirmed, beta (MCP01 Token Mismanagement & Secret Exposure … MCP10 Context Injection & Over-Sharing). |
| OWASP Agent Control Standard | exists (redirects to `agent-control-standard-acs`, 2026-09-01): a wire spec for a "Guardian Agent" that permits, denies or modifies actions; repo release v0.1.5 (2026-11-20). Its reference guardian fails open by default. |
| OTel MCP semantic conventions | confirmed at `open-telemetry/semantic-conventions-genai` v0.1.0 (2026-11-21), status Development. Span `{mcp.method.name} {target}`; `mcp.method.name` required; `gen_ai.tool.name`, `jsonrpc.request.id`, `mcp.protocol.version`, `rpc.status_code` among the others. Raw `gen_ai.tool.call.arguments`/`result` are opt-in, which gatehouse will never set (redaction). Trace context in `params._meta.traceparent`. |
| Benign tool-definition corpora | **partial:** the official MCP Registry API has server metadata only (no tools; CC0; preview). `AgenticResourceDiscovery/verified-mcp-tools` on Hugging Face (CC BY 4.0, card claims 31,411 tools with JSON schemas from 2,223 live remote servers) is the best candidate; not yet audited. |
